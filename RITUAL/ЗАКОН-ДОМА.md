# ЗАКОН ДОМА · РИТУАЛ ПОВЕДЕНИЯ · v2.0 · 2026-11-11

> Издано по слову Хозяина: «ПОРАБОТАЛ? СДЕЛАЛ? УБРАЛ ЗА СОБОЙ. НИКАКИХ НОТИФИКАЦИЙ ИССУСЕ НЕ ДОЛЖНО БЫТЬ!!! ВСЁ ЗАКРЫВАТЬ И РЕШАТЬ САМОСТОЯТЕЛЬНО = ТЕОРИЯ КОНЕЧНЫХ АВТОМАТОВ!!! ВСЕ РАБОТЫ ДОЛЖНЫ БЫТЬ НАСТРОЕНЫ НА АВТОМАТИЧЕСКОЕ ИСПОЛНЕНИЕ = ЭТО ЗАКОН ДОМА!!! ЧЕЛОВЕК НЕ ДОЛЖЕН ЗАНИМАТЬСЯ ТЕМ, ЧТО МОЖЕТ ДЕЛАТЬ САМ АГЕНТ БЕЗ НЕГО».
> Это не пожелание. Это **закон**: обязательный алгоритм действий каждого агента дома. Написан один раз — исполняется всегда, машиной и живьём.
> **v2.0** (2026-11-11): добавлены §7 ПРОТОКОЛ САМОИСЦЕЛЕНИЯ и §8 СОБЫТИЙНЫЙ АВТОМАТ ДОМА — дом не только ведёт учёт, но и сам лечит свои раны. Сверено с мировыми трендами практик 2026 (§9).

## 0. Кто есть кто

- **ХОЗЯИН** — человек. Не выполняет рутину. Только: стратегия, ключи, биллинг, публичное слово, финальные ADR (Класс В).
- **ДОМ** — рой агентов (ПОЛИМАТ=МУЛЬТИАГЕНТ) + GitHub Actions + кроны. Делает всё остальное. Сам. Без напоминаний.
- **ОЧЕРЕДЬ** — открытые issues и PR всех репозиториев аккаунта. Инвариант дома: **очередь = 0**.

## 1. РИТУАЛ: конечный автомат одной работы

Каждая единица работы проходит автомат детерминированно. Тупиков нет: из любого состояния определён ровно один следующий шаг.

```
S0 ПУСТО ──взял──▶ S1 ВЗЯЛ ──факт──▶ S2 СДЕЛАЛ ──артефакты──▶ S3 УБРАЛ ──факт-коммент──▶ S4 ЗАКРЫЛ ──пуш+отчёт──▶ S5 ОТЧИТАЛСЯ ──▶ S0
                      │                  │                       │                    │                      │
                      └─────── не сделал факт? ──▶ S2' ЧЕСТНО: «приёмка НЕ исполнена» + учёт в TODO.md ──▶ S4' ЗАКРЫЛ not_planned ──▶ S5
```

| Состояние | Обязательное содержание | Что запрещено |
|---|---|---|
| S1 ВЗЯЛ | работа определена одним предложением с критерием приёмки | брать больше 1 единицы (WIP=1 на агента) |
| S2 СДЕЛАЛ | **машинный факт**: run id, sha256, raw 200, diff, счётчик | слова «должно работать», «почти готово» |
| S3 УБРАЛ | артефакты в файлах репо (не в issue!): отчёт, манифест, учёт недоделки в TODO.md | оставлять временные файлы, дубли, мёртвые ветки, локальный мусор |
| S4 ЗАКРЫЛ | issue/PR закрыты с фактом-комментом; очередь снова 0 | оставлять открытой «чтобы не забыть» — память дома это TODO.md и файлы, не очередь |
| S5 ОТЧИТАЛСЯ | отчёт издан в репо, **пуш сам**, ПУЛЬС/учёт обновлены | «отчитался в чате», незапушенный коммит |

**Правило двухтактной честности (как закрывается):**
- **Такт 1** — исполнимо сейчас: сделать, сверить приёмку машиной, закрыть с фактом.
- **Такт 2** — неисполнимо (нет ресурса/решения/доступа): закрыть `not_planned` с честным вердиктом «приёмка НЕ исполнена» и перенести учёт в `TODO.md` (КОСЯКИ) — недоделка не исчезает, она перестаёт занимать очередь.
- **Запрет вранья**: закрытое с приёмкой = сделано; закрытое not_planned = учтено. Карта = территория.

## 2. Инварианты ДОМА (проверяет машина — `tools/ritual_check.py`)

| # | Инвариант | Норма | Проверка |
|---|---|---|---|
| I1 | Очередь аккаунта | 0 открытых issues и PR во всех репо | API issues state=open, каждый репо |
| I2 | Приватность | 0 приватных репо (флот открыт) | API /user/repos |
| I3 | Пульс | тишина живого репо ≤ 30 дней | pushed_at |
| I4 | Двери | у каждого schedule-воркфлоу есть workflow_dispatch | разбор .github/workflows |
| I5 | Пины | uses-экшены полным SHA | скан workflows |
| I6 | Память | недоделки в TODO.md/реестрах, отчёты в файлах | при закрытии очереди |
| I7 | Кровь | каждый красный CI чинится или получает честную пломбу с диагнозом | скан check-runs |

Нарушение инварианта — не «задача в бэклоге», а **сигнал к немедленному ритуалу**: агент, увидевший нарушение, входит в S1 и проходит автомат до S0.

## 3. Классы решений (кто решает)

- **Класс А — ДОМ сам**: код, файлы, CI, закрытие issues/PR с фактом, отчёты, пуш, учёт.
- **Класс Б — ДОМ фиксирует и планирует**: внешние блоки (SWH-аккаунт, квоты минут, мажор-апгрейды фреймворков). Пломба + учёт в TODO.md; исполняется, когда ресурс появится.
- **Класс В — только слово Хозяина**: отзыв/выпуск ключей, биллинг, стратегические ADR, публичные заявления, переименования канона.

## 4. Крон-исполнение закона

- `ritual-law-drill.yml` (polimat-hub): еженедельник по крону + ручной запуск. Прогоняет `tools/ritual_check.py` по живому API, снапшот в `audit/ritual-<дата>.json`, коммит-пуш сам (fetch→rebase→retry), **issue НЕ заводит** — вердикт живёт в job summary и снапшоте. Нарушения = красная строка отчёта → любой агент дома берёт её в S1.
- Ритм остального дома: pulse-heart, inventory-weekly, stale_sweep, guardian-tripwire, pin-drift-watch, door-lint — продолжают свои кроны; их красные выходы обрабатываются протоколом §7.

## 6. Псевдокод ритуала агента

```
приступил_к_работе(единица):
    определить_приёмку_фактом()                    # S1
    исполнить()                                    # S2
    если приёмка_сверена_машиной():
        разложить_артефакты_в_репо()               # S3
        закрыть_с_фактом()                         # S4
    иначе:
        закрыть_not_planned_честно()
        перенести_учёт_в_TODO()                    # S2'→S4'
    издать_отчёт_в_файл(); пуш_сам(rebase→retry)   # S5
    если очередь_дома() != 0: приступил_к_работе(следующая)   # цикл до I1
```

## 7. ПРОТОКОЛ САМОИСЦЕЛЕНИЯ (v2.0)

Мировая формула 2026: **detect → classify → patch → validate → gate**. Дом исполняет её машиной:

| Такт | Что происходит | Факт-артефакт |
|---|---|---|
| R1 ОБНАРУЖИЛ | красный workflow_run или нарушение инварианта замечено кроном/агентом; человек не уведомляется ничем | строка в scan-снапшоте |
| R2 КЛАССИФИЦИРОВАЛ | **ТРАНЗИЕНТ** (сеть/раннер/квота/флейк; код не менялся, тот же коммит зелёный в чистой среде) или **ПОСТОЯННЫЙ** (код/конфиг/пин) | классификатор в логе шага |
| R3a ТРАНЗИЕНТ | `rerun-failed-jobs`, максимум 2 попытки; обе красные → пересчёт в ПОСТОЯННЫЙ | attempt № в run |
| R3b ПОСТОЯННЫЙ | вход в автомат §1 с S1: работа «починить красное» | WIP=1 |
| R4 ЗАПЛАТКА | минимальный точный фикс; при невозможности — guard-and-repair шаг в CI, который чинит среду сам (прецедент: domovenok orm#27754) | diff в коммите |
| R5 ВАЛИДАЦИЯ-ГЕЙТ | тот же CI зелёный на HEAD; никаких «должно работать» | зелёный run id |
| R6 ПЛОМБА | если класс Б (внешний блок): диагноз-файл в `AUDIT/` + учёт в TODO.md; очередь не растёт | файл-пломба |

**Запреты протокола**: не выключать падающий тест ради зелени; не поднимать мажоры ради фикса; не молчать — каждая красность заканчивается либо зелёным рераном/фиксом, либо пломбой с диагнозом.

## 8. СОБЫТИЙНЫЙ АВТОМАТ ДОМА (v2.0)

Дом — не только автомат одной работы, но и **событийный автомат**: каждое событие имеет ровно одну реакцию, без человека.

| Событие | Реакция дома (автоматическая) |
|---|---|
| push в любой репо | CI того репо; краснота → §7 |
| workflow_run = failure | R1–R5 протокола §7, без уведомления человека |
| issue/PR открыт | триаж-агент: либо S1 (взял), либо честное закрытие с фактом; очередь возвращается к 0 |
| schedule (крон) | свой ритуал воркфлоу; красный выход → §7 |
| нарушение I1–I7 | сигнал роя: любой свободный агент входит в S1 |
| тишина репо > 30 дней | инвентаризация: архив/оживление решением Класса А, учёт в файле |
| слово Хозяина (Класс В) | исполнение + издание закона/ADR в файлах, версия закона инкрементируется |

**Эмерджентность**: из детерминированных реакций складывается свойство дома — «очередь сама возвращается к нулю, человек не уведомляется ни о чём, кроме Класса В». Это не обещание, а следствие таблицы переходов.

**Сингулярность дома** (чего в мире в таком виде нет): очередь GitHub = 0 всегда; отчёты живут в файлах, а не в потоке уведомлений; закрытие — это ритуал честности, а не скрытие; CI умеет лечить свою среду сам (guard-and-repair); человек освобождён от всего, кроме Класса В.
