## 1. Общие сведения

Проект ПОЛИМАТ — мультиагент-архитектор аккаунта GitHub `rtynbirf` (создан 2022-12-01).
На дату мандата: 40 репозиториев (24 публичных, 16 приватных). После реструктуризации 2026-11-08:
созданы `polimat-hub` (место сверок) и `polimat-vault` (пломбы), выполнены MERGE трилогии Windows,
ABSORB `rumu`, 3 DELETE; затем `polimat-vault` свёрнут в каталог `vault/` внутри hub — итог 38 репозиториев.

Цель настоящего ТЗ — зафиксировать требования к состоянию аккаунта, при котором:
(а) ни одна операция необратима без пломбы; (б) веб-продукты работают без внешних серверов
(кроме явно перечисленных исключений); (в) каждое утверждение о состоянии проверяется машиной,
а не памятью агента.

## 4. Функциональные требования

### 4.1 Безопасность

- **Т-1 (токены).** Активный токен живёт не дольше одной сессии; хранится только в переменной
  окружения; в файлы, коммиты, чаты и ZIP не попадает ни в каком виде — включая маскированные
  фрагменты. После мандата — отзыв владельцем (подтверждение: HTTP 401).
- **Т-2 (утечки).** Скан `ghp_|github_pat_|gho_|ghs_` по всем деревьям и полной истории
  затронутых репо обязателен до любого push. Эталон: прогон 2026-11-08 — 38 ревизий, 0 вхождений;
  единственный `ghp_` в README был плейсхолдером и заменён на `***`.
- **Т-3 (механизмы GitHub).** На всех репо включены secret scanning и push protection;
  канонические ветки защищены от force-push. Эталон: боевой тест на расходном репо —
  force-push отклонён живым ответом GH013 «Cannot force-push to this branch».

### 4.2 Резервирование и пломбы

- **Т-4 (пломба).** Любая деструктивная операция (DELETE, rewrite, merge, замена дерева) =
  git-бандл в `polimat-hub/vault/` + строка SHA256 в `MANIFEST.sha256` + запись в
  `RESTRUCTURE-LOG.md` ДО операции.
- **Т-5 (офлайн).** Копия пломб существует вне GitHub (текущая: `polimat-vault-offline-2026-11-08.zip`,
  90 файлов). Копия в том же аккаунте резервом не считается.
- **Т-6 (обратимость).** Удаление репо GitHub допускает восстановление 90 дней — этот срок
  фиксируется в журнале как окно отката каждой DELETE-операции.

### 4.3 Тяжёлые артефакты

- **Т-7 (порог).** Git-дерево — для истории текстов и кода. Артефакты >50 МБ в дерево коммитов
  не кладутся: билды — в Releases/asset, данные — в LFS или шифрованный `release-vault`.
  Цель к 2027: ни одного репо >500 МБ в дереве (правило 4 `ARCHITECTURE.md`).
- **Т-8 (ruvson-lyrics).** Части КУБ-2026 живут в Release `media-vault` с SHA256 каждой части.
  Релиз доводится из черновика до published (черновик виден только владельцу).
  Дерево переписывается `git filter-repo` по 5 известным sha1 ТОЛЬКО по команде Хозяина,
  после пломбы текущего состояния (у агентов живые клоны).
- **Т-9 (singulyar).** 1541 МБ мелких файлов: до выбора механизма (LFS против Releases против
  внешнего хранилища) — расчёт квот и трафика, решение оформляется ADR. Слепого переписывания нет.

### 4.4 Local-first (стандарт — в `05_LOCAL_FIRST.md`)

- **Т-10 (библиотеки).** Сторонние библиотеки вендорятся: pinned версия, sha256 равен оригиналу
  CDN, SRI-атрибут в разметке. Эталон: transformers.js 3.7.5, hls.js 1.5.13, webtorrent 2.5.1 —
  sha256 совпал с jsdelivr; three.js r128 — sha384 совпал с integrity из страницы.
- **Т-11 (модели).** Инференс локальный: transformers.js с `allowRemoteModels=false`, модели
  только из `./models/`, скачивание — `tools/fetch_models.py` (stdlib, без токена, атомарная
  запись, MANIFEST.sha256). Модели в git не кладутся. Доработка: pin ревизии HF вместо main.
- **Т-12 (шрифты).** Только self-hosted woff2 с подмножествами (кириллица/латиница).
  Эталон: `singulyar/fonts/` — Manrope и Unbounded (cyr+lat), запрос к Google Fonts удалён,
  подтверждено headless-проверкой.
- **Т-13 (внешние вызовы).** Переводчик и плеер: 0 обращений к mymemory, translate.*, itorrents.
  Каждый оставшийся внешний адрес — явная запись в белом списке с обоснованием
  (текущий белый список — раздел 4 `05_LOCAL_FIRST.md`).
- **Т-14 (откат).** Честная лестница: локальный файл → CDN той же версии → аварийная старая
  версия. Молчаливой подмены источника нет: страница сообщает, что взято.

### 4.5 Верификация и учёт

- **Т-15 (независимость).** Своё о своём не верифицируется своим скриптом. Либо другой инструмент,
  либо другой агент, либо другой канал (live-API против локального бандла). Эталон: кросс-чек
  2026-11-08 пакетов внешнего агента + доказательство rumu сравнением tree-хэшей.
- **Т-16 (инвентарь).** Истина о составе аккаунта — API-снимок `repo_inventory.py`, а не память.
  `verify_architecture.py` — ежеквартально; `edinyy-svod` перегенерируется по факту 38 репо
  (сейчас в нём 37).
- **Т-17 (канон).** Один факт — один канонический репозиторий. Поглощённые тела живут в
  `merged-from/`/`diffs/` с пломбами истории, а не дублирующими репо.
- **Т-18 (журнал).** Запись в `RESTRUCTURE-LOG.md` предшествует деструктивной операции;
  свидетельство (машинный вывод) появляется после.

## 5. Нефункциональные требования

- **Н-1 (офлайн-пригодность).** Каждый веб-продукт открывается и работает без сети, кроме
  явно перечисленных исключений из белого списка.
- **Н-2 (stdlib-only).** Инструменты агента — только стандартная библиотека Python 3.10+,
  ноль зависимостей, офлайн-запуск.
- **Н-3 (лимиты GitHub).** Файл в git <100 МБ; asset релиза ≤2 ГБ; квота LFS учитывается до
  выбора механизма, а не после ошибки пуша.
- **Н-4 (совместимость).** Не ломать живые клоны агентов: rewrite истории — только по явной
  команде Хозяина и после пломбы.

## 6. Ограничения

1. Песочница агента не имеет доступа к huggingface.co — модели скачивает Хозяин локально
   (`python3 tools/fetch_models.py --set mt asr-tiny`, ~650 МБ, в корне плеера и singulyar).
2. API-поле `size` — ленивый счётчик (репо 20 КБ показывал 0): вес мерить фактическим клоном/бандлом.
3. Анонимные запросы к API лимитированы; видимость приватных репо проверяется HTML-пробой
   (200/404), а не кодом ответа API.
4. Полный состав `polimat-hub` и `vault/` на сервере подтверждается только живым токеном.
