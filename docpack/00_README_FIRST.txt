ИСТОРИЯ ВЕРСИЙ
==============
   v2.1 - фикс строки RESULT в bat\1_verify_pack.bat: были пропущены
          закрывающие "!" в delayed expansion ("!OKCNT  FAIL=!" съедалось
          как одно пустое имя переменной). На результат проверки не влияло:
          17/17 OK подтверждено живым прогоном на машине Хозяина.
   v2.0 - исправление брака v1 (имена и батники, см. ниже).

ЧТО БЫЛО СЛОМАНО В v1 И КАК ПОЧЕНО В v2
=======================================
1. Имена файлов. В v1 имена внутри архива были кириллицей в UTF-8, но без
   служебного флага UTF-8 (bit 11, EFS). Проводник Windows на русской
   машине в этом случае читает имена в кодовой странице CP866 - отсюда
   кракозябры вида «╨ó╨ò╨Ñ╨¥╨÷╨í╨Ü╨₧╨ò_╨ù╨É╨ö╨É╨¥╨÷╨ò». Виноват сборщик (zip
   без флага), а не твой Windows.
   В v2 все имена файлов в архиве - ТОЛЬКО ЛАТИНИЦЕЙ. Имя из ASCII-символов
   не зависит ни от кодовой страницы, ни от распаковщика, ни от языка
   Windows - ломаться нечему. Содержимое файлов - русский язык, UTF-8.
2. Батников в v1 не было вообще. В v2 - три, все рабочие (раздел «БАТНИКИ»).

КОДИРОВКИ В ПАКЕ
================
   *.md          - UTF-8 без BOM, русский язык (VS Code / Notepad Win10+).
   00_README...  - UTF-8 С BOM: Блокнот на любом Windows определяет его
                    безусловно, даже на старых сборках.
   *.bat, *.ps1  - ЧИСТЫЙ ASCII: ни одного байта вне ASCII, поэтому вывод
                    в cmd не зависит от CP866 / CP1251 / chcp 65001.
                    Сообщения инструментов - английские, русские пояснения -
                    здесь и в документах. Это осознанное решение: батник без
                    не-ASCII байтов не может сломаться кодировкой в принципе.
   Концы строк   - CRLF во всех файлах пака.
   SHA256SUMS.txt - ASCII-манифест: «хэш пробел путь» (пути через \).

БАТНИКИ
=======
   START_HERE.bat         меню: [1] целостность, [2] скан токенов,
                          [3] открыть этот README, [4] список файлов, [0] выход.
   bat\1_verify_pack.bat  SHA-256 каждого файла против SHA256SUMS.txt
                          через certutil - Python не нужен.
   bat\2_scan_tokens.bat  поиск ЖИВЫХ GitHub-токенов в текстах пака
                          (PowerShell, полный шаблон: префикс + 36+ символов).
                          Описания шаблонов в доках (04, 09, 10, 12) -
                          заведомо мёртвые тексты - отфильтровываются самим
                          шаблоном, ложных срабатываний нет.
   Батники досье (DOSSIER_GO.bat, POLIMAT_AUTO_PUSH.bat, POLIMAT_FINISH.bat,
   POLIMAT_MERGE.bat) - в своём паке RLHF_DOSSIER_PACK_v2.zip, сюда их
   половинчатые копии не клались: без своих патчей и тел PR они мертвы.

КАК ПОЛЬЗОВАТЬСЯ
================
   1. Распакуй архив ЦЕЛИКОМ (правый клик - «Извлечь всё...»), не из окна архива.
   2. Запусти START_HERE.bat.
   3. Пункт [1] должен дать: RESULT: OK=17 FAIL=0 (манифест покрывает все 17
      файлов пака, кроме самого SHA256SUMS.txt - себя он захэшировать не может).
      Любой FAIL - архив побит при передаче, скачай заново.
   4. Пункт [2] должен дать: RESULT: PASS.
