# РЕГЛАМЕНТ ТЯЖЁЛЫХ ФАЙЛОВ · ПОЛИМАТ / rtynbirf

- Версия: 1.0, 2026-11-08. Развивает правило 4 `ARCHITECTURE.md`: git — для истории текстов,
  цель к 2027 — ни одного репо >500 МБ в дереве.

## 1. Пороги и классификация

| Артефакт | Куда | Примечание |
|---|---|---|
| Код, тексты, схемы (<50 МБ на файл) | git-дерево | штатно |
| Один файл 50–100 МБ | LFS или Releases; в git нельзя по лимиту GitHub (>100 МБ файл отклоняется) | Н-3 |
| Билд (сборка приложения, «одна страница с base64-пейлоадом») | Releases/asset | билд ≠ медиа: урок ruvson-lyrics |
| Медиа, данные, модели | Releases частями / LFS / внешнее хранилище | по ADR с расчётом квот |
| Секреты/архивы ассетов | `release-vault` (шифрованный офсайт) | кластер А |

## 2. Кейс ruvson-lyrics (канонический пример)

- Факты: 5 частей `RUVSON_QUANTUM_v5.part1of5…part5of5`; 4×89 342 035 + 89 342 039 =
  446 710 179 B = 446,7 МБ = 82,9 % веса репо (дерево 514 МБ по verify_architecture.py).
- Природа: ОДНО одностраничное HTML-приложение «КУБ-2026 · Квантовая Сансара v3»,
  разрезанное на 5 томов; HTML+JS+встроенный base64-пейлоад; аудиофайлов в дереве нет.
  Сначала помечено как «медиа», исправлено по замечанию Хозяина «там только тексты» —
  в журнал внесена правка «Билд, не медиа» (коммит ab3840c, ждёт push).
- Ша1 частей (свидетельство git-sha1, part1/part5 перепроверены локально после ревокации
  токена): cda1c72e2225f9394c063cda98b1ab72998abbd7, 6e4a0a6b15637b5965e8d0f0edfb5dcd006a07d7,
  c0e480f515eee0573b4b07af1a23b97eb85c6f63, c5e9839aadd2618ba00ec1eb66161c1c096367d3,
  11da60f5b8f12890e4b8220b3f5bb14a5f088775.
- Состояние: части перенесены в Release `media-vault` (пока черновик, виден только владельцу).
  Дерево НЕ переписано: 5 blob'ов остаются в истории.
- План Ф2: published релиз → сверка SHA256 → пломба → `git filter-repo` по 5 sha1 →
  force-push только по команде Хозяина → свежий клон + `git fsck` + размер.

## 3. Кейс singulyar

- 1541 МБ — тысячи мелких файлов (HTML-приложения, JS, шрифты, данные караоке).
- Релизами не лечится: релиз — про крупные файлы, а тут суммарный вес дерева.
- Варианты для ADR-005:
  1. **LFS** — прозрачно для HTML, но бесплатная квота 1 ГБ хранилища + 1 ГБ/мес трафика;
     при публичном монолите трафик улетит мгновенно.
  2. **Releases** с архивами-томами — не решает: дерево всё равно остаётся.
  3. **Разделение репо** (код отдельно, контент отдельно) — против правила канона? Нет:
     контентный репо может быть каноном контента, код — каноном кода. Требует ADR.
  4. **Rewrite истории + перенос контента** в release-vault/внешнее хранилище.
- Решение принимает Хозяин после расчёта квот; исполнение — после пломбы.

## 4. Процедура выноса из истории (общая)

```bash
# 0. ПЛОМБА (06, раздел 3) — до всего.
# 1. Снять бандлы всех агентов: у живых клонов история останется старой — это учтено.
pip install git-filter-repo   # единственная не-stdlib зависимость инструмента
git filter-repo --invert-paths --strip-blobs-bigger-than 50M <репо>
# или точечно по sha1:
git filter-repo --invert-paths --path download/konveyer/v5_parts <репо>
# 2. force-push --force с защищённой ветки — только по команде Хозяина.
# 3. Свежий клон, git fsck, размер, сверка tree-хэшей канонических путей.
```

- После rewrite у всех живых клонов устаревает история: повторный клон обязателен, старые
  клоны дальше вести нельзя (иначе склеим переписанное со старым).

## 5. Лимиты GitHub (не эвристика, а границы)

| Параметр | Значение |
|---|---|
| Файл в обычном git | <100 МБ (больше — push отклоняется) |
| Рекомендуемый размер репо | <1 ГБ, жёсткое предупреждение около 5 ГБ |
| Release asset | до 2 ГБ на файл (части >2 ГБ резать) |
| LFS бесплатно | 1 ГБ хранилища, 1 ГБ/мес трафика |
| Draft release | виден только владельцу — не считать опубликованным |

## 6. Проверка результата

```bash
git rev-list --objects --all | \
  awk '{print $2}' | xargs -I{} stat -c '%s {}' {} 2>/dev/null | sort -rn | head -20
```

Критерий Ф2: первые строки списка <50 МБ, кроме случаев, прямо разрешённых ADR.
