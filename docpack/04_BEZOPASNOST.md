# РЕГЛАМЕНТ БЕЗОПАСНОСТИ · ПОЛИМАТ / rtynbirf

- Версия: 1.0, 2026-11-08. Действует для агентов и Хозяина на всех операциях аккаунта.
- Эталоны прецедентов зафиксированы 2026-11-08 в журналах `polimat-hub`.

## 1. Принципы

1. Секрет существует в двух местах: менеджер секретов владельца и переменная окружения
   активной сессии. Третьего места не существует.
2. Прежний токен никто не читает «для истории» — он отозван (подтверждение: HTTP 401).
   Прецедентная ценность цикла: выдача → работа → отзыв в тот же день.
3. Приватное не равно секретное: приватные репозитории сканируются теми же правилами.
4. UNKNOWN ≠ FALSE: «скан ничего не нашёл» пишется вместе с командой прогона и датой.

## 2. Токены

| Правило | Требование |
|---|---|
| Хранение | только `export GITHUB_TOKEN=…` в оболочке сессии; ни в файлы, ни в коммиты, ни в ZIP, ни в чат — даже фрагментами и «для примера» |
| Срок жизни | одна сессия; после — отзыв владельцем; подтверждение отзыва = ожидаемый 401 на живом запросе |
| Scope | минимально достаточный: read/write по репо; delete_repo выдавать только на фазы, где удаление реально нужно |
| Выводы скриптов | инструменты никогда не печатают значение токена в лог; ошибки API цитируются без заголовков |

## 3. Сканы утечек (до любого push)

```bash
# по рабочим деревьям
rg -n 'ghp_[A-Za-z0-9]{36}|github_pat_[A-Za-z0-9_]{20,}|gho_[A-Za-z0-9]{36}|ghs_[A-Za-z0-9]{36}' .
# по полной истории затронутого репо
git log -p --all | rg -n 'ghp_[A-Za-z0-9]{36}|github_pat_'
```

- Обязателен для каждого репо, в которое пришёл push, и для каждого ZIP-пакета перед отдачей.
- Эталон 2026-11-08: 38 ревизий — 0 вхождений; единственный литерал `ghp_` в README был
  плейсхолдером и заменён на `***`.
- Внутри самого пакета запрещено хранить маскированные фрагменты реальных токенов:
  маска «ghp_AIwc…MM» — уже утечка метаданных. Пишется: «токен сессии №N, отозван».

## 4. Механизмы GitHub (включаются на все 38 репо)

| Механизм | Назначение | Статус |
|---|---|---|
| Secret scanning | находит уже утёкшие секреты в истории | включить в Ф0 |
| Push protection | блокирует push с секретом на входе | включить в Ф0 |
| Branch protection | запрет force-push на канонических ветках | включить в Ф0 |
| Правило против пломб | force-push канона только после пломбы и по команде Хозяина | процесс |

живым ответом GH013 «Cannot force-push to this branch», remote не изменился — механизм работает,
стенд после теста удалён. Гейт С128 singulyar — надмножество polimat-guard, конфликта нет.

## 5. Инцидент-протокол

1. Утечка обнаружена → немедленный отзыв токена (владелец), не дожидаясь выяснений.
2. `git log -p --all` по затронутым репо → граница распространения.
3. Если секрет ушёл в публичное: rewrite истории (`git filter-repo`) после пломбы,
   плюс перевыпуск всех секретов, которые могли быть в той же зоне.
4. Запись в `RESTRUCTURE-LOG.md`: факт, границы, действия, свидетельства.
5. Разбор причин — без поиска виновных, с правкой регламента через ADR.

## 6. Сторонние зависимости

- Каждый vendor-файл имеет pinned версию и sha256, сверённый с оригиналом (протокол —
  `12_VERIFIKACIYA.md`). Эталон: transformers.js 3.7.5, hls.js 1.5.13,
  webtorrent 2.5.1 — байт в байт с jsdelivr; three.js r128 — sha384 совпал с integrity.
- Замена vendor-файла на файл с того же имени, но другой контрольной суммой, — приёмка не
  проходит (защита от подмены цепочки поставок).
- `__pycache__` и прочий мусор сборки в пакеты не входит (замечание к раунду 2 — закрыть в Ф4).

## 7. Жёсткие пути (hardcoded)

- Инструменты не содержат абсолютных путей чужих машин. Найденное — дефект:
  `build_fonts.py` с жёстко прописанным домашним каталогом внешнего агента — правится при
  переносе в канон (Ф4).
