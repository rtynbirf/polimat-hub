## ВОЛНА 0

### W0-1 `release-vault` — флаки vault-integrity → предложение **«ИММУНИТЕТ»**
- **МИР:** Google борется с флаками не героизмом, а иммунной системой: авто-кворантин
  при превышении порога, «считать сломанным только при 3 падениях подряд», монитор
  изменения уровня флаки.
- **СВОЁ:** прогон vault-integrity пишет `audit-runs/<дата>.json` (хеш-сводка сверок) —
  не булево, а временной ряд. Судья-шаг в конце job: падение → один авто-повтор →
  повтор зелёный ⇒ ран помечен `flaky-suspect`, 3 флаки из 5 прогонов ⇒ workflow
  заводит issue «иммунный ответ» в release-vault. Свёртка «тренд вместо табло»
  переносима на любой пайплайн дома (универсально).
- **ГОТОВО =** в репо лежат `audit-runs/*.json` за 3 прогона + 3× `success`.

### W0-2 `universal-agent` — verify-канон падает → предложение **«КАНОН-ФРОСТ»**
- **МИР:** golden-file/contract-тестирование: эталон замораживается, CI сравнивает.
- **СВОЁ:** канон check.py замораживается в `canon/EXPECTED.sha256`; при расхождении
  шаг печатает не «FAIL», а диф-приговор «что именно отошло от канона и какой командой
  пересобрать эталон легитимно». Оракул становится учителем: ошибка сама несёт путь
  к лечению. Заморозка меняется только отдельным коммитом-«стрижкой».
- **ГОТОВО =** run зелёный; в логе падения (когда случится) виден диф-приговор.

### W0-3 `polymath-os` — Lint красный → предложение **«ХРАПОВИК»**
- **МИР:** lint-baseline (ratchet): фиксируешь текущий долг, падение — только при росте.
- **СВОЁ:** `lint-debt.txt` с числом. Линтер падает если долг вырос, зелёный если равен/
  меньше; число печатается вsummary CI как метрика здоровья. Цель-храповик: в W2 число
  = 0, файл удаляется торжествующей записью в журнале. Храповик нельзя крутить назад
  незаметно — число монотонно убывает (эмерджентное: долг становится видимой траекторией).
- **ГОТОВО =** CI зелёный; `lint-debt.txt` существует; число не выросло за 3 прогона.

### W0-4 `singulyar` — оракул пина тела → предложение **«ДВОЙНОЙ ПИН»**
- **МИР:** lockfile-дисциплина: пин управляется машиной, а не руками.
- **СВОЁ:** пин в MANIFEST.json клетки rumu становится двусторонним: оракул не только
  сверяет, но при легитимном обновлении тела (по пломбе-коммиту) сам переписывает пин
  отдельным ботом-шагом и оставляет след `pin-history.log`. Пин превращается из камня
  в геномный маркер с родословной.
- **ГОТОВО =** run зелёный; `pin-history.log` содержит запись последнего пина с SHA коммита.

### W0-5 dependabot-PR `universal-agent` → предложение **«ПАРОМ»**
- **МИР:** dependabot `groups`: все обновления экосистемы одним PR (wildcard для
  github-actions — прямой паттерн из документации).
- **СВОЁ:** во всех репо с dependabot.yml — группа `tide-*` (обновления actions — одним
  PR по вторникам). Дом дышит приливным ритмом: вторник = прилив, остальная неделя
  тихая. Бонус из мира: для тяжёлых экосистем разбивку делать `update-type`
  (patch/minor/major) — безопасный паром и аварийный паром.
- **ГОТОВО =** 2 PR universal-agent закрыты; в dependabot.yml есть блок `groups`.

### W0-6 PR «genome: cell agryp» → предложение **«ГЕНОМНЫЙ ADR»**
- **МИР:** ADR (architecture decision record): решение переживает переписку.
- **СВОЁ:** решение по геномному PR фиксируется в commons как `adr/GNN-<номер>-<имя>.md`
  (контекст/решение/следствия/реверс-условия) — принятый ген получает порядковый номер
  в геноме, отказанный — хранится как «выбракованная мутация» (учит рой на отказах).
  Эмерджентно: геном растёт файлами-генами, а не сообщениями в PR.
- **ГОТОВО =** PR resolved; в commons лежит ADR с номером гена и ссылкой на PR.

### W0-7 РУЧНАЯ МИНУТА соцпревью ×26 → предложение **«ЭЛЕВАТОР-26»**
- **МИР:** GitHub не даёт API для Social preview — мировой опыт: только UI, вручную.
- **СВОЁ:** генерим `elevator-26.html` (в hub, не публикуем): 26 строк — имя репо,
  прямая ссылка `github.com/rtynbirf/<repo>/settings#repository-preview` и raw-ссылка
  на готовый PNG рядом. Хозяин проходит дорожку: клик → upload → следующий. Минута
  превращается из раскопок в спуск на элеваторе. Честная пометка: полностью автоматизировать
  нельзя (нет API), полувтоматизировать — можно.
- **ГОТОВО =** файл в hub; 26/26 превью стоят (проверка глазами Хозяина).

### W0-8 отзыв токенов → предложение **«ТОКЕН-МЕТАБОЛИЗМ»**
- **МИР:** fine-grained токены с минимальным scope, secret scanning + push protection
  на аккаунте — мировой стандарт гигиены.
- **СВОЁ:** токен = субстрат с обменом веществ: выдаётся на сессию, в конце сессии
  агент пишет в `RESTRUCTURE-LOG.md` строку «токен: выдан/отозван», а центральный
  ПУЛЬС (W2-5) раз в неделю сверяет живые токены аккаунта с журналом и рапортует
  Хозяину лишние. Оборот токенов становится observable.
- **ГОТОВО =** старые токены отозваны; в журнале есть записи выдачи/отзыва.

## ВОЛНА 1

### W1-1 rumu: DELETE объявлен, репо жив → предложение **«САРКОФАГ, НЕ МОГИЛА»**
- **МИР:** GitHub archive — обратимая дехидратация: ссылки, звёзды, история живы;
  удаление необратимо и ломает внешние ссылки.
- **СВОЁ:** вариант Б усиливается до третьего пути: `archived: true` + README-указатель
  «тело клетки перенесено: singulyar ветка rumu, пломба vault/...» + правка реестра
  операций (DELETE → ARCHIVE) по пломбе. Репо становится честным надгробием-указателем,
  противоречие растворяется: реестр и реальность совпадают. Универсальный закон роя:
  «мы не удаляем — мы анабиозируем».
- **ГОТОВО =** rumu archived; README содержит указатель; журнал исправлен.

### W1-2 счётчики врут (25 vs 26/41) → предложение **«ЧИСЛА-НИКОГДА-РУКАМИ»**
- **МИР:** профильные тулзы 2026 — авто-refresh счётчиков через Actions (числа
  пересобираются машиной, а не пишутся руками).
- **СВОЁ:** скрипт `pulse_counters.py` в hub: тянет API → сам патчит бейджи профиля,
  кластерную таблицу, константы сайта → коммит «счётчик-животное» по расписанию.
  Запрет доктринального уровня: **ни одно число в текстах дома не пишется человеком**.
  Счётчик становится органом, а не ремеслом.
- **ГОТОВО =** 25→26/41 везде заменено машиной; расписание в workflow.

### W1-3 сайт отстал → предложение **«ВИТРИНА-ДЫШИТ»**
- **МИР:** data-driven статические сайты: контент из JSON, деплой по событию и cron.
- **СВОЁ:** сайт ест тот же `inventory.json` (единый источник с hub), на витрине
  появляется секция «ЗДОРОВЬЕ ДОМА»: зелёные/красные пайплайны + дата последнего
  ПУЛЬСа. Публичная честность как эстетика — никто в мировой практике не показывает
  красные свои CI на витрине; здесь это доктрина Honesty.
- **ГОТОВО =** HTTP 200; числа совпадают с API; секция здоровья рендерится.

### W1-4 singulyar 1584 МБ → предложение **«СЕРДЦЕ-НА-ДИЕТЕ»**
- **МИР:** GitHub предупреждает с 50 MiB, блокирует с 100 MiB; большие медиа — Releases
  или LFS; история чистится git filter-repo.
- **СВОЁ:** трёхходовка: (1) медиа → Release-ассеты (стабильные URL, без LFS-квоты),
  (2) `MANIFEST.json` с SHA256 всех вынесенных тел (доктрина vault переносится в репо),
  (3) filter-repo по пломбе для истории. Плюс «таможня 50 МБ»: pre-commit/workflow-страж
  отвергает файлы >50 MiB ДО того, как они попадут в дерево — диета как метаболизм, а не
  как разовая операция.
- **ГОТОВО =** `size_kb` ≤ 512 000; MANIFEST сверяется скриптом; таможня стоит.

### W1-5 ruvson-lyrics 526 МБ → предложение **«КОРПУС-НА-ДИЕТЕ»**
- **МИР:** то же (Releases + filter-repo).
- **СВОЁ:** сингулярное различение: текст (ценно, маленько, git), аудио (тяжёлое,
  офсайт) — маршрутизация по природе материала: тексты живут в git вечно, аудио —
  в release-vault (шифрованный офсайт) с хеш-указателями в MANIFEST. Корпус 65 треков
  становится «партитурой в доме, оркестром в сейфе».
- **ГОТОВО =** `size_kb` ≤ 512 000; у каждого аудио — хеш-указатель в MANIFEST.

### W1-6 5 зависших dependabot-веток voice-atlas-llm → предложение **«ПРИЛИВ»**
- **МИР:** dependabot сам открывает PR; ветки без PR — мусор от прошлых конфигов.
- **СВОЁ:** один скрипт «прилив»: находит ветки `dependabot/*` без открытого PR,
  батчем открывает PR (или удаляет по пломбе). Ритм W0-5: приливы по вторникам,
  линька веток — по пятницам. Рой получает двухтактный дыхательный цикл.
- **ГОТОВО =** у каждой из 5 веток либо открытый PR, либо её нет.

## ВОЛНА 2

### W2-1 homepage у 19 репо → предложение **«ОКНО КАЖДОМУ МИРУ»**
- **МИР:** homepage-поле — прямой SEO/UX-сигнал, мировой стандарт для продуктов.
- **СВОЁ:** не «ссылка на сайт вообще», а анкор на личную карточку репо на витрине
  (`rtynbirf.github.io/#<repo>`). Каждый мир получает своё окно в дом; клик с поля
  repo ведёт точно в его секцию. Патчится одним скриптом через PATCH.
- **ГОТОВО =** homepage 26/26, каждая ссылка ведёт на свой анкор.

### W2-2 topics ≥3 ×41 → предложение **«ТАКСОНОМИЯ-ГЕНОМ»**
- **МИР:** GitHub topics — до 20 тегов, главный канал обнаруживаемости внутри GitHub.
- **СВОЁ:** словарь тем в hub: три слоя — `кластер` (swarm/atlas/os/…), `предмет`
  (rust/llm/karaoke/…), `форма` (engine/registry/agent/…). Скрипт валидирует каждый
  репо против словаря и PATCH-ит. Таксономия — геном, темы — фенотип; фенотип не может
  мутировать вразрез с геномом. Универсально: governance вместо россыпи.
- **ГОТОВО =** len(topics)≥3 ×41; все темы из словаря; скрипт зелёный.

### W2-3 ветки-хвосты → предложение **«ЛИНЬКА»**
- **МИР:** GitHub auto-delete head branches после merge — настройка репозитория.
- **СВОЁ:** рой линяет по квартальному ритму: ветки старше 30 дней без движения →
  пломба-бандл → удаление; включить auto-delete во всех репо разом. Змей (snake на
  профиле) и рой синхронно сбрасывают кожу — образ дома становится операцией.
- **ГОТОВО =** лишних веток нет; auto-delete включён; в журнале — пломбы.

### W2-4 markitdown форк → предложение **«ПРИЁМНЫЙ ОРГАН»**
- **МИР:** форк-этикет: NOTICE об апстриме, синхронизационные workflow, чистка
  апстрим-веток.
- **СВОЁ:** README-блок «ПРИЁМНЫЙ ОРГАН»: это трансплантат с апстрима microsoft/markitdown,
  живёт по правилам дома (обложка LABS, доктрина), ежемесячный sync-upstream workflow,
  10+ апстрим-веток прунятся после сверок по пломбе. Трансплантат не скрывается —
  декларируется и приживляется.
- **ГОТОВО =** политика в README; sync-workflow зелёный; лишних веток нет.

### W2-5 ПУЛЬС на все → предложение **«ЕДИНОЕ СЕРДЦЕ»**
- **МИР:** hub-and-spoke мониторинг: один агрегатор обходит периферию, а не 41
  дублирующий бота.
- **СВОЁ:** один централизованный workflow в polimat-hub: обходит 41 репо API
  (база `repo_inventory.py` уже есть!), пишет `PULSE.md` (таблица: репо × последний
  прогон × вес × ветки), красным заводит issues в их репо. Каждое репо перестаёт
  носить собственный ПУЛЬС — сердце одно, сосуды длинные. stdlib-only, по этике дома.
- **ГОТОВО =** еженедельный зелёный прогон; PULSE.md свежее 7 дней; issues на красных.

### W2-6 лицензии MIT+REUSE → предложение **«ПАСПОРТ ОРГАНА»**
- **МИР:** fsfe reuse-tool: `reuse lint` в CI из коробки; SPDX-теги — мировой стандарт
  атрибуции.
- **СВОЁ:** `reuse lint` встраивается в Единое Сердце (W2-5) как проверка «паспорта»:
  каждый публичный орган имеет паспорт (LICENSE + REUSE-заголовки), безпаспортные —
  в отчёте. Паспортный стол дома = один шаг, не 26 configure-циклов.
- **ГОТОВО =** верификация 26/26 зелёная; безпаспортных нет.

### W2-7 профиль-бейджи → предложение **«ЧЕСТНЫЙ БЕЙДЖ»**
- **МИР:** профильные виджеты 2026 — автообновляемые SVG-статы (stats, streak, trophy).
- **СВОЁ:** вместо ванильной славы — сгенерённый бейдж **«ЗДОРОВЬЕ ДОМА»**:
  `N зелёных / M красных пайплайнов · аудит 2026-11-08 · 41 репо`. Обновляется Единым
  Сердцем. Мир флексит стриками; дом флексит честностью — уникальный профильный паттерн,
  которого нет в мировых подборках. (typing-SVG и веркель-плитки отвергнуты ранее —
  не возвращаем.)
- **ГОТОВО =** бейдж в профиле, числа совпадают с последним PULSE.

## ВОЛНА 3

### W3-1 публикация экспозиций F → предложение **«ГОСТИНЫЙ РЕЖИМ»**
- **МИР:** GitHub Pages из репо — мировой стандарт публикации одностраничников.
- **СВОЁ:** приватные экспозиции получают «гостевой режим»: решение о публикации
  = переключение видимости + строка в журнале (обратимо, как и всё у дома). На витрине
  — «музейный коридор»: единая страница-маршрут по трём экспозициям (язык / веб /
  свод), каждый зал открывается с обложкой LABS. Гости ходят по коридору, кладовка
  остаётся приватной.
- **ГОТОВО =** решение в журнале; при «да»: Pages 200, коридор на витрине.

### W3-2 PHOENIX-11 рассекречивание → предложение **«ЛИСТ ВЗЛЁТА»**
- **МИР:** launch-кит: обложка-соцкарта + одностраничник «что это и зачем».
- **СВОЁ:** заготовка «листа взлёта» делается ЗАРАНЕЕ в приватной ветке (обложка LABS,
  README-герой, страница-презентация с тремя скринами). Рассекречивание = один пуш.
  Рой готовит фениксу гнездо до того, как феникс сгорит — подготовка переживает решение.
- **ГОТОВО =** ветка-гнездо существует; при «да» — пуш и обложка живая.

### W3-3 archived-политика 90 дней → предложение **«ЗАСЫПАЮЩИЙ ЛЕС»**
- **МИР:** sunset-политики open source: явный статус «не поддерживается» вместо
  тихого тления.
- **СВОЁ:** бот раз в месяц находит репо без пуша 90 дней → кандидат в журнале →
  `archived: true` + sunset-строка в README: «спит с <дата>. Просыпается по слову
  Хозяина» (архивация обратима — их же правило №8). Лес дома сам сообщает, кто заснул.
- **ГОТОВО =** список кандидатов в журнале; archived стоят; спящие помечены.

### W3-4 квартальный макро-аудит → предложение **«СЕЗОННАЯ ЛИНЬКА»**
- **МИР:** ретроспективы/OKR-циклы; diff-of-states как первичный артефакт.
- **СВОЁ:** макро-аудит генерится Единым Сердцем как **дифф двух инвентарей**:
  новые миры, вес-дельты, красные пайплайны, судьба спящих — таблица «что выросло /
  что усохло» открывает новый AUDIT-файл. Человек (или агент) не пишет аудит заново —
  он читает дифф и добавляет интерпретацию. Аудит становится сезоном, а не подвигом.
- **ГОТОВО =** новый AUDIT начинается с diff-таблицы двух JSON-снимков.

## ПРОТОКОЛЬНЫЕ УСИЛЕНИЯ

### «Правила роя» → предложение **«ЖИЗНЬ ПРЕДЛОЖЕНИЯ»**
Каждое предложение (включая этот файл) имеет статус-жизненный цикл, пишемый прямо
в JSON-слепок: `seed` (родилось) → `grown` (обросло критериями и свидетелями) →
`planted` (влито в ROADMAP/AUDIT) → `composted` (отказано, но оставлено как урок).
Отказ — тоже питательная среда: компост роя кормит следующие такты.

### «Приём волны» → предложение **«ЭСКАЛАЦИЯ ТИШИНЫ»**
`blocked` старше 14 дней поднимается автоматически: Единое Сердце (W2-5) заводит
issue Хозяину с меткой `эскалация`. Тишина в рое не может быть вечной — она становится
событием с датой и адресатом.

## СКВОЗНАЯ ИДЕЯ · **«РОАДМАП-КАК-ДАННЫЕ»** (самое эмерджентное)

**МИР:** AGENTS.md — README-для-агентов (60k+ проектов, стандарт OpenAI+Google 2025)
и llms.txt v2 — машиночитаемые корни сайтов. Мир уже кормит агентов текстами.
- **СВОЁ — шаг дальше мира:** карта и предложения дома живут **не только документом,
  но и данными**: `proposals-2026-11-08.json` (id, статус жизни, мир-практика, цель,
  критерий-done, роль). Единое Сердце читает JSON и само ведёт issues, статусы и
  эскалации. Документ — для человека; данные — для роя; оба растут из одного корня.
  Это делает аккаунт самописцем: roadmap перестаёт быть текстом, который читают, —
  становится программой, которая работает.
- **ГОТОВО =** JSON-слепок лежит рядом, валиден (`json.tool` зелёный), Единое Сердце
  (W2-5) при первом прогоне читает его.
