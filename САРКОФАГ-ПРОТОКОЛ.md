# САРКОФАГ-ПРОТОКОЛ (П-71, polimat-hub#95)

**Зачем:** перед любой перезаписью истории тяжеловесов (singulyar, ruvson-lyrics) фиксируется content-addressed идентичность данных — манифест data-package с git blob sha1 на каждый файл, чтобы после filter-repo можно было доказать, что контент пережил операцию без потерь.

**Порядок (строго):**
1. Манифест: `python3 tools/sarcofag_manifest.py --api repo <имя> [--ref <ветка>] --out sarcofag/<имя>-datapackage.json` (режим B — `--local <клон>`, `--deep` добавит sha256).
2. ADR: короткая запись решения (что переписываем, зачем, чем) в issue полимата.
3. `git filter-repo` — ТОЛЬКО по явной команде Хозяина (БЛОК ХОЗЯИНА, исполнителем не запускается).
4. Сверка: генерируется свежий манифест, сравниваются `count`, `total_bytes` и множества `gitBlobSha1` с саркофагом до операции; расхождение = красный разбор.

**Приёмка:** манифесты валидны (json.loads), `count`/`total_bytes` совпадают с суммой ресурсов, поле `truncated` честно.

**Готовые саркофаги:** `sarcofag/singulyar-datapackage.json` и `sarcofag/ruvson-lyrics-datapackage.json` — сняты коммитером волны с живых деревьев той же командой и лежат в репо как эталон «до».
